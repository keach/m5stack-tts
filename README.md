# m5stack-tts

M5Stack Basic（ESP32）向けのPlatformIOプロジェクトです。

電源投入時には3秒間のスプラッシュ画面を表示してから、SDカード、音声合成、Wi-Fiなどの初期化を開始します。スプラッシュ表示中にボタンBを長押しすると設定・診断モードへ入ります。

## 実装状況

### 実装済み

- PlatformIOによるM5Stack Basic向けのビルド、書き込み、シリアルモニター環境
- 電源投入時の3秒間のスプラッシュ画面

## 初回セットアップ

Python 3.10以上を使用してください。

このプロジェクトでは、他のPlatformIOプロジェクトとフレームワークやツールチェーンが衝突しないよう、PlatformIO Coreの保存先をプロジェクト専用の `.pio-core` に分離しています。このディレクトリはGit管理対象外で、初回ビルド時に必要なパッケージがダウンロードされます。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

### Flashパーティション

4MB Flashのうちアプリ領域を十分に確保するため、`platformio.ini`で`min_spiffs.csv`を指定しています。アプリ領域はOTA用に1,966,080 bytesずつ2面を維持し、使用していないSPIFFS領域を131,072 bytesへ縮小します。NVS領域の位置と容量は標準構成から変わりません。

パーティション構成を変更した後の初回書き込みは、M5Stack BasicをUSBで接続して行ってください。SPIFFSの内容は保持されませんが、このプロジェクトの辞書とログはmicroSDを使用するため影響しません。

従来のパーティション構成へ切り戻す場合は、`platformio.ini`から次の行を削除し、USB経由でもう一度書き込みます。

```ini
board_build.partitions = min_spiffs.csv
```

## Wi-Fi・天気設定

サンプルをコピーして、接続先のSSIDとパスワードを設定します。

```sh
cp include/secrets.example.h include/secrets.h
```

`include/secrets.h` にWi-FiのSSIDとパスワード、OpenWeather APIキー、天気を取得する地点の緯度・経度を設定してください。このファイルはGitの管理対象外です。

## 地震情報設定

サンプルをコピーし、通知対象とする都道府県を最大8件まで指定します。このファイルはGitの管理対象外です。

```sh
cp include/earthquake_config.example.h include/earthquake_config.h
```

```cpp
constexpr const char* EARTHQUAKE_TARGET_PREFECTURES[] = {
    "東京都",
    "神奈川県",
    "千葉県",
};
constexpr bool EARTHQUAKE_USE_SANDBOX = false;
constexpr bool EARTHQUAKE_ALLOW_SANDBOX_AUDIO = false;
```

Wi-Fi・NTPの初期化後、P2P地震情報 JSON API v2のWebSocketへ接続します。緊急地震速報（コード556）は対象地域にかかわらず画面を復帰して表示し、対象地域なら同一イベントにつき1回専用警告音を、対象外なら短い音を鳴らします。対象外から対象地域へ変化した場合は、専用警告音も追加で1回鳴らします。

地震情報（コード551）は最大震度、震源、マグニチュード、発生時刻を60秒間表示します。対象地域なら画面を復帰して論理的に同じ地震につき1回だけ短い音を鳴らします。対象外なら画面を復帰せず、画面が点灯中の場合だけ表示し、音は鳴らしません。表示優先度は緊急地震速報、地震情報、気象アラート、通常画面の順です。

緊急地震速報は最終更新から2分間、取消報は30秒間表示し、その後は元の画面へ戻ります。受信中も天気取得、SDログ、Ambient・ThingSpeak送信は継続します。履歴画面へ戻る場合は最新履歴を再取得します。音声読み上げは後続Issueで対応します。

受信したEEWと対象地域の地震情報はmicroSDへUTF-8のNDJSONとして保存します。EEWと地震情報は別々に管理し、1世代500件、各10世代（最大5,000件ずつ）を保持します。新世代の作成時に10世代を超える場合は最古ファイルを削除します。Web画面から削除前に各世代を手動でバックアップできます。

WebSocket受信処理では履歴を最大4件のRAMキューへ追加するだけとし、SD書き込みはメインループで行います。書き込みは最大3回、1秒間隔で再試行し、それでも失敗したレコードはリアルタイム表示を優先して破棄します。再起動時は最新世代と有効な改行終端レコード数を復元し、最終行が途中で切れたファイルには追記せず新世代へ移行します。

動作試験では `EARTHQUAKE_USE_SANDBOX` を `true` にするとP2P地震情報のサンドボックスへ接続します。サンドボックス由来の情報は画面に試験表示し、通常は音を鳴らしません。立ち会い試験で音も確認する場合に限り `EARTHQUAKE_ALLOW_SANDBOX_AUDIO` を `true` にしてください。試験後は両方とも必ず `false` に戻してください。

P2P地震情報は情報の内容や到達性を保証するものではありません。この機能は補助的な表示として利用し、防災上の判断は気象庁や自治体などの公的情報に従ってください。

Ambientへ送信する場合は、サンプルをコピーし、作成したチャネルのチャネルIDとライトキーを設定します。このファイルもGitの管理対象外です。

```sh
cp include/ambient_secrets.example.h include/ambient_secrets.h
```

```cpp
constexpr unsigned int AMBIENT_CHANNEL_ID = 12345;
constexpr char AMBIENT_WRITE_KEY[] = "your-write-key";
```

Ambientには、`d1`から順に気温、湿度、気圧、直近1時間雨量、高温アラート閾値、現在の降雨状態、Wi-Fi RSSI、OpenWeatherのweather condition IDを送信します。`d8` はOpenWeatherが定義する数値の天気分類で、例えば晴天は`800`、雲は`801`〜`804`、雨は`500`番台です。すべての送信でOpenWeather APIから正常に気象情報を取得した時刻を `created` として指定し、画面下部にも同じ時刻を `API Fetched` として `yyyy.mm.dd. hh:mm` 形式でAmbient送信結果とともに表示します。時刻が同期されていない場合はAmbient送信を行わず、SDカードへの記録は継続します。

Ambientへの送信に失敗したデータは、microSDの `/ambient_queue.ndjson` へ保存します。次回の天気更新時に新しいデータと合わせ、最大10件ずつAmbientの一括送信APIへ再送します。送信に成功したレコードだけをキューから除去します。応答が失われた場合などはAmbient側に同じ `created` のデータが重複する可能性があります。

ThingSpeakへ送信する場合は、サンプルをコピーし、チャネルIDとWrite API Keyを設定します。このファイルもGitの管理対象外です。チャネルIDを `0`、またはキーを空のままにするとThingSpeak送信を無効化できます。AmbientとThingSpeakの両方に認証情報を設定すると二重送信します。

```sh
cp include/thingspeak_secrets.example.h include/thingspeak_secrets.h
```

```cpp
constexpr unsigned long THINGSPEAK_CHANNEL_ID = 1234567;
constexpr char THINGSPEAK_WRITE_API_KEY[] = "your-write-api-key";
```

ThingSpeakは通常時に `https://api.thingspeak.com/update.json` へJSON形式で送信します。Write API Keyに対応するチャネルへ保存し、レスポンスのチャネルIDが設定値と一致することを確認します。`created_at` にはOpenWeather APIから正常に現在天気を取得した時刻をUTCで指定します。送信項目は次のとおりです。

| Field | フィールド名（日本語 / English） | 値 |
| --- | --- | --- |
| `field1` | 温度 / Temperature | 気温（℃） |
| `field2` | 湿度 / Humidity | 湿度（%） |
| `field3` | 気圧 / Atmospheric Pressure | 気圧（hPa） |
| `field4` | 天気コード / Weather Code | OpenWeather weather condition ID |
| `field5` | 降水確率 / Probability of Precipitation | 直近3時間予報の降水確率（%） |
| `field6` | 高温アラート / High Temperature Alert | なし `0`、発報中 `30` / `35` / `40` |
| `field7` | Wi-Fi受信信号強度 / Wi-Fi RSSI | RSSI（dBm） |
| `field8` | 降雨アラート / Rain Alert | なし `0`、発報中 `1` |

ThingSpeakへの送信に失敗したデータは、認証情報を含めずmicroSDの `/thingspeak_queue.ndjson` へ保存します。SDロック取得や書き込みに一時的に失敗した場合は最大10件をRAMへ保持し、5秒間隔でSDキューへの保存を再試行します。次回の天気更新時に現在データをキュー末尾へ追加し、古いものから最大10件をBulk Update APIで再送します。成功した対象行だけをキューから削除し、失敗時は次回へ持ち越します。同じ `created_at` のレコードは重複登録しません。単件送信とBulk送信のリクエスト開始間隔は15秒以上とし、間隔内の更新は待機せずキューへ保存します。

ThingSpeakの無料ライセンスはチャネル更新間隔が15秒以上に制限されています。本プロジェクトは送信処理側でも15秒の間隔を保証し、間隔内のデータは再送キューへ保存します。ThingSpeak送信に失敗しても天気表示、読み上げ、アラート、Ambient送信は継続します。

### ThingSpeakでの送信停止監視

`thingspeak/monitor_uploads.m` をThingSpeakのMATLAB Analysisへコピーし、2つのReactから実行すると、気象チャネルへの送信停止と復旧をメールで確認できます。最終entryから30分以上経過した状態を停止と判定します。

監視状態は気象データとは別の非公開チャネルに保存します。監視用チャネルには次の2フィールドを作成してください。

| Field | 名前の例 | 値 |
| --- | --- | --- |
| `field1` | `Upload status` | 正常 `0`、停止 `1` |
| `field2` | `Minutes since last entry` | 最終entryからの経過分。entryがない場合は `-1` |

設定手順は次のとおりです。

1. ThingSpeakで監視用の非公開チャネルを作成し、上記2フィールドを有効にする
2. Account > My ProfileでAlerts API Keyを作成する
3. Apps > MATLAB Analysisで新しいAnalysisを作成し、`thingspeak/monitor_uploads.m`を貼り付ける
4. スクリプト冒頭の気象チャネルID、Read API Key、監視チャネルID、監視チャネルのRead/Write API Key、Alerts API Keyを設定する
5. MATLAB Analysisの`Save and Run`で、監視チャネルへ初期状態が1件記録されることを確認する
6. Apps > Reactで、次の停止検知用Reactと復旧検知用Reactを作成する

停止検知用Reactは、気象チャネルに30分間entryが追加されなかったときだけMATLAB Analysisを実行します。

- Condition Type: `No Data Check`
- 対象チャネル: 気象チャネル
- 無通信時間: `30 minutes`
- Action: `MATLAB Analysis`
- Code to execute: 手順3で作成したAnalysis
- Options: `Run action only the first time the condition is met`

復旧検知用Reactは、気象チャネルへentryが追加されるたびにMATLAB Analysisを実行します。本プロジェクトでは`field4`に正のOpenWeather weather condition IDを保存するため、これを実行条件として使用します。

- Condition Type: `Numeric`
- 対象: 気象チャネルの`field4`
- 条件: `is greater than 0`
- Test Frequency: `On Data Insertion`
- Action: `MATLAB Analysis`
- Code to execute: 手順3で作成したAnalysis
- Options: `Run action each time condition is met`

気象チャネルが公開の場合、`sourceReadKey`は空のまま使用できます。非公開の場合はRead API Keyを設定してください。認証情報を設定したMATLAB AnalysisのコードはGitHubなどへ公開しないでください。

ThingSpeakのAccount > My ProfileにあるTime Zoneは、利用地点に合わせて設定してください。このプロジェクトでは`Tokyo`を想定します。MATLAB Analysis内の`datetime('now')`と`thingSpeakRead`の時刻はこのアカウント設定に従うため、コードではUTCへ付け替えず、同じタイムゾーンのまま経過時間を計算します。

MATLAB Analysisは実行のたびに監視状態と経過分を記録します。正常状態で初めて実行した場合は、監視チャネルへ基準状態を保存するだけでメールを送りません。初回実行時点ですでに30分以上停止している場合は停止通知を送ります。その後は正常から停止、または停止から正常へ変化したときだけ通知し、同じ状態の間は通知を繰り返しません。通知APIが失敗した場合は状態遷移を保存せず、次のReact実行で通知を再試行します。

復旧検知用Reactは気象entryの追加直後に実行されるため、正常時の`field2`は通常0分付近になります。停止検知用Reactが発火した場合は、`field1=1`、`field2`は30分以上になります。

動作確認では、まずM5Stackから通常どおり送信した状態でAnalysisを手動実行し、`field1=0`が記録され、メールが届かないことを確認します。次にM5Stackの電源を切るかThingSpeak送信を停止し、最終entryから30分経過後にAnalysisを実行して、`field1=1`と停止通知を確認します。同じ状態でもう一度実行したときは通知されません。最後に送信を再開し、新しいentryが追加された後にAnalysisを実行して、`field1=0`と復旧通知を確認します。

当初はTimeControlから10分ごとにMATLAB Analysisを実行する構成を想定していました。しかし、RecurringとOne Timeの両方で予定時刻に実行されず、One Timeが約3時間遅れて実行される挙動を確認したため、ThingSpeak公式のチャネル無通信監視例に沿ったReact構成へ変更しました。不要になったTimeControlは、遅延実行や監視チャネルへの重複書き込みを避けるため削除してください。

初回の停止試験では、停止検知用Reactは発火したものの、監視チャネルへ`field1=0`、`field2=0`が記録されました。原因は、ThingSpeakがアカウントのタイムゾーンで返した最新entry時刻をコード内でUTCへ付け替え、実際より未来の時刻として扱っていたことです。経過時間が負数になり、`max(0, ...)`によって0分へ補正されていました。現在は明示的なタイムゾーン変更を行わず、アカウント時刻同士で比較します。

ThingSpeak Alertsには30分あたり2件までの送信制限があります。この監視は補助機能であり、生命・安全に関わる唯一の監視経路として使用しないでください。

起動時にWi-Fiへ接続した後、NTPサーバーから時刻を取得します。時刻は日本標準時（JST）で液晶とシリアルモニターに表示されます。液晶のデフォルト表示形式は `yyyy.mm.dd. ddd hh:mm` で、設定モードから秒表示へ切り替えられます。

現在の天気、気温、湿度、気圧、直近1時間の雨量と、直近4件の3時間予報は、起動時と10分ごとにOpenWeatherから取得します。ボタンAを押すと両方を手動更新できます。現在天気と予報は別々に取得するため、片方が失敗しても、もう片方の取得済みデータは引き続き利用します。ボタンAで更新した場合、次の自動更新はボタンを押してから10分後です。

OpenWeatherの天気分類が `Clouds` の場合は、現在天気と予報の画面表示・音声読み上げを雲量（`clouds.all`）に応じて次のように細分化します。雲量が欠落している場合や0〜100%の範囲外の場合は、従来どおり `Clouds`／「曇り」とします。CSVログ、Ambient連携、降雨判定ではAPIから取得した元の天気分類を維持します。

| 雲量 | 画面表示 | 音声読み上げ |
| ---: | --- | --- |
| 0〜10% | `Mostly clear` | ほぼ晴れ |
| 11〜25% | `Few clouds` | 雲は少なめ |
| 26〜50% | `Scattered` | 雲がまばら |
| 51〜84% | `Mostly cloudy` | 雲が多め |
| 85〜100% | `Overcast` | 曇り |

## 予報画面

通常の天気画面でボタンCを押すと予報画面へ切り替わります。OpenWeatherの5 day / 3 hour forecast API（`/data/2.5/forecast`）から取得した直近4件について、予報時刻、天気分類、予想気温、降水確率、3時間予想雨量を表示します。画面切替だけではAPIへ再リクエストしません。

- ボタンA: 現在天気と予報を手動更新
- ボタンB: 表示中の画面を読み上げる。発話中は停止
- ボタンC: 現在天気 → 予報 → 地震履歴 → 現在天気の順に切り替える

予報画面の下部には予報APIの取得成功時刻を `API Fetched` として表示します。1分間ボタン操作がない場合は、現在天気画面へ自動的に戻ります。予報の取得中、取得失敗、未取得も画面に表示し、更新に失敗した場合は直前に取得できた予報を保持します。

## 地震履歴画面

microSDに保存された地震情報と緊急地震速報を、受信日時の新しい順に最大20件表示します。画面へ入るたびに最新履歴を読み直します。

- ボタンA: 古い履歴へ1件ずつ移動する。最後の履歴の次は最新へ戻る
- ボタンB: 選択中の履歴の詳細を表示する
- ボタンC: 現在天気画面へ戻る
- 詳細画面のA/B/C: 同じ履歴の概要へ戻る

固定ラベルは英語、震源地・対象地域は日本語で表示し、受信日時はJSTで表示します。長い情報は省略するため、全文はWeb画面で確認してください。microSD未認識、履歴なし、読み込み中、SD使用中、読み込みエラーを区別して表示します。不完全な末尾行や不正なレコードは読み飛ばします。

履歴の読み込みは少量ずつ行い、天気更新や受信処理を継続します。リアルタイムの地震表示が優先され、表示終了後は最新履歴の概要へ戻ります。無操作1分で現在天気画面へ戻り、A/B操作と詳細から戻る操作でタイマーを更新します。画面スリープにも対応し、復帰の最初の押下は操作に使用しません。

## 画面スリープ

画面スリープはデフォルトで有効になっており、現在天気・予報・設定・診断画面では、5分間ボタン操作がないとLCDとバックライトをスリープさせます。設定画面からスリープを無効にするか、無操作時間を1分、5分、10分、30分から選択できます。ESP32自体は動作を続けるため、スリープ中も10分ごとの天気更新、Ambient送信、SDログ、アラート判定、音声処理は継続します。

ボタンA/B/Cのいずれかを80ミリ秒以上押すと画面を復帰します。短い入力はノイズとして無視します。最初の押下は復帰だけに使用されるため、更新・読み上げ・画面切替は実行されません。一度ボタンを離した後の次の押下から通常操作に戻ります。画面が復帰した場合は、ボタン、アラート通知、定時予報読み上げのいずれが原因だったかをシリアルログへ記録します。

高温・降雨アラートが発生した場合は現在天気画面へ自動復帰します。夜間も画面は復帰しますが、警告音と音声は再生しません。定時予報読み上げの開始時は予報画面へ自動復帰します。自動復帰後も、設定した無操作時間が経過すると再びスリープします。

画面表示時の明るさは20%、40%、60%、80%、100%から選択でき、デフォルトは従来の明るさに近い40%です。スリープから復帰した場合も設定した明るさへ戻ります。設定・診断画面でも復帰に使った最初の押下を消費し、スリープ前のページ、選択項目、編集中の値を維持します。アラーム音または音声テストの再生中はスリープせず、再生終了時から無操作時間を計測し直します。


### 通知時の画面復帰と音声優先順位

気象更新時の通知は、各アラートが個別に画面や音声を操作するのではなく、次の順序で処理します。

1. 高温、現在降雨、降雨予報の条件と新規発報を判定する
2. 同じ更新で成立したアラートをまとめ、復帰先と音声の優先順位を決定する
3. 警告音より先に画面を復帰する
4. 夜間でなければ、優先された1件の警告音と音声を再生する

| 新規発報 | 復帰先 | 音声 |
| --- | --- | --- |
| 高温 | 現在天気画面 | 高温 |
| 現在降雨 | 現在天気画面 | 現在降雨 |
| 降雨予報 | 予報画面 | 降雨予報 |
| 高温 + 現在降雨 | 現在天気画面 | 高温 |
| 高温 + 降雨予報 | 現在天気画面 | 高温 |
| 現在降雨 + 降雨予報条件成立 | 現在天気画面 | 現在降雨。降雨予報は新規発報しない |

優先順位は高温、現在降雨、降雨予報の順です。0:00から6:00までは同じ優先順位で画面だけを復帰し、警告音と音声は再生しません。すでに発報済みの状態が継続しているだけの場合は再度復帰しません。ボタンによる復帰、定時予報読み上げ、予報画面の1分タイムアウトは従来どおりです。

## ローカルWebダウンロード

Wi-Fi接続後、起動画面と設定モードの診断画面に表示されるIPアドレスへ、同じローカルLAN上のPCまたはスマートフォンから `http://<IP>/` でアクセスできます。トップページには公開対象ファイルのサイズとダウンロードリンクを表示します。地震履歴については、世代数、各世代の件数・サイズ、次回削除予定ファイル、および最新5件の概要も表示します。

| データ | ダウンロードURL |
| --- | --- |
| 天気ログ | `/download/weather` |
| 高温アラート | `/download/temperature-alerts` |
| 降雨アラート | `/download/rain-alerts` |
| Ambientキュー | `/download/ambient-queue` |
| ThingSpeakキュー | `/download/thingspeak-queue` |
| 降雨予報アラート | `/download/rain-forecast-alerts` |
| 地震履歴 | `/download/earthquake-history?type=earthquake&generation=000001` |
| EEW履歴 | `/download/earthquake-history?type=eew&generation=000001` |

地震履歴の世代番号はWebトップページのリンクから指定します。種別、6桁の世代番号、現在保持しているファイルの組み合わせだけを許可し、任意パスによる取得はできません。アップロード、更新、削除も提供しません。ファイルはRAMへ一括読み込みせず、microSDからそのまま送信します。SDカードが利用できない場合や他のSD処理と競合した場合は `503 Service Unavailable`、対象ファイルがまだ作成されていない場合は `404 Not Found` を返します。

このWeb画面には認証がありません。ローカルLAN内だけで利用し、ルーターのポート転送などでインターネットへ公開しないでください。

## SDカード

FAT32でフォーマットしたmicroSDカードを電源投入前に挿入してください。カードが認識されると、天気情報の取得成功時に `/weather.csv` へ次の形式で追記します。

```csv
datetime,weather,temp_c,humidity_pct,pressure_hpa,rain_1h_mm
2026-07-13 12:00:00,Clouds,28.4,72,1008,0.0
```

SDカードがない場合や初期化に失敗した場合も、時計と天気表示は継続します。

### 日本語表示フォント

通常画面、予報画面、高温・降雨・降雨予報アラートでは、microSDカードの
`/Japanese16.vlw`をTFT_eSPI Smooth Fontとして読み込みます。`sdcard`
ディレクトリの内容をmicroSDカードのルートへコピーしてください。

```text
/Japanese16.vlw
/aq_dic/aqdic_m.bin
```

フォントがない、またはmicroSDを認識できない場合も起動を継続し、対象画面を
従来の英語で表示します。フォントの認識結果は起動時のシリアルログと診断画面の
`JP font`で確認できます。設定・診断画面、スプラッシュ画面、ボタン操作説明、
送信状態、API取得日時は英語表示のままです。

日本語フォントはNoto Sans CJK JP Regular 16pxを元に、ASCII、日本語の句読点、
ひらがな、カタカナ、全角形、摂氏記号、JIS X 0208第一水準漢字2,965字を収録して
います。元フォントはSIL Open Font License 1.1で提供され、ライセンス全文は
`src/fonts/NOTO-SANS-JP-LICENSE.txt`に収録しています。

生成元のリビジョンとSHA-256は`support/GenerateJapaneseFont.java`で固定して
います。Java 17以降を使い、次のコマンドで同じ`.vlw`を再生成できます。初回は
固定したNoto Sans CJK JPをダウンロードします。

```sh
java support/GenerateJapaneseFont.java
```

すでに元フォントを取得している場合は、次のように指定できます。固定した
SHA-256と一致しないファイルは使用しません。

```sh
java support/GenerateJapaneseFont.java --font /path/to/NotoSansCJKjp-Regular.otf
```

現在の生成物は3,417グリフ、896,219 bytesです。Smooth Fontは描画時に
microSDを参照し、グリフ管理情報として約41KBのHeapを使用する見込みです。
実機での読み込み時間と実際のHeap使用量は起動ログへ出力します。

## AquesTalk ESP32 SDK

AquesTalk ESP32 Small辞書版2.4.4の評価版SDKは、再配布条件に従ってGit管理対象外の `vendor/aquestalk/aquestalk-esp32_s` に配置します。PlatformIOはこのローカルSDKを `lib_extra_dirs` から読み込みます。

漢字かな混じり文を音声合成するには、`sdcard` ディレクトリの内容をmicroSDカードのルートへコピーしてください。実機上の辞書パスは次のとおりです。

```text
/aq_dic/aqdic_m.bin
```

評価版には発音制限があります。継続的な開発や製品版としての利用には、AQUESTの使用ライセンスが必要です。

ライセンスキーを取得した場合は、Git管理対象外の `include/secrets.h` に設定します。空文字の場合は評価版として動作します。

```cpp
constexpr char AQUESTALK_LICENSE_KEY[] = "";
```

起動時に辞書と音声合成エンジンを初期化します。ボタンBを押すと表示中の現在天気または予報を内蔵スピーカーで読み上げ、発話中にもう一度ボタンBを押すと停止します。現在天気が未取得の場合は固定のテスト文、予報が未取得の場合は取得できない旨を読み上げます。

音声とアラーム音のデフォルト音量は50%です。設定モードから10%刻みで調整できます。

## 設定・診断モード

電源投入時のスプラッシュ画面でボタンBを1秒以上長押しすると、各サービスの初期化後に設定・診断モードへ入ります。短いボタンノイズによる誤操作を避けるため、メニュー操作も80ミリ秒以上の押下で確定します。

- ボタンA: 前の項目
- ボタンB: 選択・実行
- ボタンC: 次の項目

時計の分表示・秒表示、音量0〜100%（10%刻み）、画面スリープの有効・無効、無操作時間、画面の明るさ、3件の予報自動読み上げ、アラーム音テスト、固定文の音声テスト、各サービスの診断結果、ファームウェア情報を操作・確認できます。メニューは1ページ最大5行で表示し、ヘッダーには `SETTINGS 1/3` のように現在ページと総ページ数を表示します。ボタンA/Cで全項目を通し順に移動し、ページ境界を越えると自動的に前後のページへ切り替わります。末尾と先頭の間も循環し、診断画面やファームウェア情報画面から戻った場合は元の選択項目とページを維持します。

`Firmware info`では、ビルド元の直近Gitタグ、7文字のコミットID、dirty状態、HEADコミット日時（JST）を確認できます。同じ情報は起動時のシリアルログにも出力されます。タグがない場合は`untagged`、Git情報を取得できない場合は`unknown`を表示します。

予報の各登録枠は1行にまとめ、有効・無効、時、分を横並びで表示します。選択中の部分だけが反転し、ボタンA/Cで `On/Off`、`Hour`、`Minute` の順に移動します。ボタンBで有効・無効を切り替え、時は `00`〜`23`、分は `00`、`15`、`30`、`45` の順に循環します。確定時刻は `HH:MM` 形式で表示します。同じ時刻を複数の枠で有効にした場合は、番号が最も小さい枠だけを有効として保存します。従来の保存形式を引き続き使用するため、すでに保存されている設定時刻もそのまま読み込めます。編集した値はページを移動しても保持し、`Save and exit` を選んだときに画面設定を含むすべての値をNVSへ保存して通常の天気画面へ戻ります。サウンドテストではアラートログや通知状態を変更しません。

## 予報の自動読み上げ

有効な登録時刻になると、通常の10分更新で保持している直近4件の予報を読み上げます。自動読み上げのための追加APIリクエストは行いません。同じ時刻を複数枠へ設定した場合も読み上げは1回だけで、各枠の最終実行日はNVSへ保存されるため、同じJST日付での再起動後も重複しません。

指定時刻に電源が入っていない、NTP時刻が未同期、予報未取得、または音声サービスが利用できない場合は、その回を静かにスキップし、後追いでは再生しません。自動読み上げは他の発話より優先され、開始時に再生中の音声を停止します。読み上げ中はAPI更新と高温・降雨通知を開始せず、ボタンBで停止できます。読み上げ終了後は通常処理へ戻り、保留されていた定期更新条件を次のループで評価します。

診断画面では、microSD、AquesTalk辞書、音声サービス、日本語フォント、Wi-Fi、NTP時刻、OpenWeather取得状態を確認できます。

## 高温アラート

現在気温が30℃・35℃・40℃以上になると、画面にそれぞれ「注意」「警告」「危険」を表示して `/temperature_alerts.csv` に記録します。30℃はオレンジ文字、35℃は赤文字、40℃は赤い見出し帯に白文字で表示します。6:00から24:00まではアラーム音と音声でも通知し、0:00から6:00までは画面表示とログ記録だけを行います。

警告音は880Hz、音の間隔は120msです。30℃は90msを2回、35℃は180msを2回、40℃は270msを3回鳴らします。複数の閾値へ同時に初回到達した場合は各閾値を記録し、画面・警告音・音声は最高閾値だけを使用します。

各閾値は独立して管理されます。通知後、気温が閾値より1℃以上低くなり、かつ前回通知から3時間以上経過すると再通知可能になります。その後、再び閾値以上になると新しいアラートとして扱います。状態はESP32のNVSへ保存されるため、再起動後も引き継がれます。

```csv
datetime,temperature_c,threshold_c,audio_played
2026-07-15 14:00:00,30.2,30,true
2026-07-15 14:40:00,35.1,35,true
2026-07-15 15:10:00,40.2,40,true
```

## 降雨アラート

OpenWeatherの現在天気が `Rain`、`Drizzle`、`Thunderstorm` のいずれかになったとき、非降雨から降雨への変化として1回だけ通知します。直近1時間雨量 `rain.1h` は、警告画面、音声、ログに使用します。

6:00から24:00までは880Hz・90msを2回（間隔120ms）のアラーム音と「雨が降っています」という音声で通知し、0:00から6:00までは画面表示とログ記録だけを行います。同時に高温アラートが発生した場合は、高温アラートの音声を優先します。

雨でない観測が2回連続すると再通知可能になります。現在の更新間隔では約20分に相当します。降雨状態はNVSへ保存するため、雨が続いている間に再起動しても重複通知しません。

```csv
datetime,weather,rain_1h_mm,audio_played
2026-07-18 15:20:00,Rain,1.4,true
```

降雨ログは高温アラートとは別の `/rain_alerts.csv` へ記録します。高温と降雨が同時の場合、画面上部では高温警告を優先します。

## 降雨予報アラート

OpenWeatherの5 day / 3 hour forecast APIで取得した直近1件について、降水確率が50%以上、かつ3時間予想雨量が0.1mm以上の場合に通知します。現在すでに雨が降っている場合は、降雨予報の新規通知を行いません。追加のAPIリクエストは行わず、起動時・10分ごと・ボタンAによる既存の予報更新結果を利用します。

通知時は予報画面へ復帰し、条件が有効な間は現在天気画面と予報画面の上部に `RAIN FORECAST: 70 %` の形式で表示します。現在天気画面の表示優先順位は、高温アラート、現在降雨アラート、降雨予報アラート、通常表示の順です。上位の警告が解除され、降雨予報がまだ有効な場合は降雨予報表示へ戻ります。

6:00から24:00までは880Hz・90msを2回（間隔120ms）のアラーム音と、3時間以内の降雨可能性・降水確率・予想雨量を音声で通知します。0:00から6:00までは画面表示とログ記録だけを行います。

条件成立中は予報枠が進んでも再通知しません。条件を満たさない直近予報を2回連続で確認すると再通知可能になります。状態はNVSへ保存されるため、再起動後も同じ降雨予報について重複通知しません。

```csv
datetime,forecast_at,probability_pct,rain_3h_mm,audio_played
2026-07-29 15:00:00,2026-07-29 18:00:00,70,2.5,true
```

降雨予報ログは `/rain_forecast_alerts.csv` へ独立して記録します。
